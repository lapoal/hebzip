# hebzip

דחיסה ללא אובדן של **טקסטים קצרים בעברית ובאנגלית** - הודעות, מכתבים, מודעות, פתיחות של ערכים. הכלי מקטין
אותם הרבה יותר מדוחסים כלליים כי הוא מגיע עם ידע מוקדם: טבלאות של מילים, זוגות מילים והתווים שבין המילים,
שנבנו מוויקיפדיה ומרשימת המילים העברית של fastText (25.3 MB למצב העברי `fast`, ועד 191 MB למצב הגדול ביותר).
הידע הזה הוא כל הסוד, ולכן כל השוואה למטה אומרת כמה ידע מוקדם כל כלי מביא איתו.

זה כלי מחקר ולא תחליף ל-zstd: הוא **איטי** (עשרות אלפיות שנייה לטקסט קצר כשהוא נשאר טעון, שניות לתהליך חדש;
ל-zstd מספיקה כאלפית שנייה), הוא צריך טבלאות גדולות, והיתרון שלו הכי גדול בטקסטים קצרים.

אפשר לנסות בדפדפן: [האתר](site/) מריץ את `fast` לעברית ואת `en_fast` לאנגלית; הטקסט לא יוצא מהדפדפן.
ההסבר המלא באנגלית: [README.md](README.md).

## תוצאות

נמדד ב-22/11/2026 **על מחשב נייד אחד** (Intel i3-1215U, ‏11.7 GB RAM, Windows 11, Python 3.12.10) בפקודה
`python -m atar.bench run`. כל טקסט נדחס לבד; כל חבילה נפתחה והושוותה בית-בית. המספרים: בתים בחבילה, ובסוגריים
ההפרש מול המצב הטוב ביותר שלנו באותה קבוצה. טקסטים שאולי היו בקורפוס שממנו נבנו הטבלאות לא נכנסים לקבוצות
(בדיקת חפיפה לא מצאה אף אחד).

הקבוצות: פתיחות ויקיפדיה (5), ערכים חדשים בוויקיפדיה (נוצרו בנובמבר 2026, אחרי שהקורפוס נלקח), טקסטי הפרויקט
(מכתבים, מודעות, סיפור, יומן, מסה - **נכתבו על ידי מודל בינה מלאכותית בשביל הפרויקט**, אנשים ומקומות בדויים),
תגובות אמיתיות (10 תגובות פייסבוק ציבוריות ממאגר OMILab; לא מצורפות - נבנות מחדש מהמאגר).

איך לקרוא את זה ביושר:

- הטענה צרה: **הודעות קצרות בעברית (ובאנגלית), עם טבלאות של 25-191 MB שמגיעות עם הכלי.** שאר הכלים (חוץ מהמילון
  הקטן של brotli ומהקבצים האנגליים של paq8px ‏-8LT) מתחילים ריקים ולומדים רק מהטקסט עצמו - ולכן טקסט קצר קשה להם.
  זו לא טענה "טוב יותר מ-PAQ" באופן כללי; בטקסטים ארוכים הפער קטן.
- מחשב אחד, ריצה אחת. הגדלים מדויקים וניתנים לשחזור; הזמנים תלויים במחשב.

## התחלה מהירה

Python 3.12 ומעלה:

</div>

    git clone https://github.com/lapoal/hebzip
    cd hebzip
    pip install numpy numba zstandard pyppmd

<div dir="rtl">

הטבלאות אינן במאגר (ראו [tables/README.md](tables/README.md)): מורידים את קובץ הטבלאות מדף ה-Releases, פותחים
אותו בתיקיית הפרויקט, ואז:

</div>

    python -m hebzip.ops.convert_tables
    python -m hebzip compress letter.txt letter.hz             # ברירת המחדל: fast
    python -m hebzip compress --mode max_plus letter.txt letter.hz
    python -m hebzip compress --mode en_fast note.txt note.hz
    python -m hebzip decompress letter.hz letter.txt
    python -m hebzip serve --modes fast,max                    # נשאר טעון, בקשות JSON בשורות

<div dir="rtl">

החבילה זוכרת את המצב שלה; חבילה נפתחת רק עם אותן טבלאות והגדרות שבהן נוצרה. הקלט חייב להיות UTF-8, והבתים
המקוריים חוזרים בדיוק.

## איך זה עובד

1. **מילים והתווים שביניהן.** הטקסט מתפצל למילים ולתבנית - כל השאר (רווחים, פיסוק, ספרות, מילים לא מוכרות, ניקוד כשכבה).
2. **מילון לפי שכיחות.** כל מילה מוכרת היא מספר השורה שלה ברשימה ממוינת לפי שכיחות; מילים נפוצות - מספרים קטנים.
3. **מנבאים ומערבל-אמון.** כמה ערוצים נותנים הסתברות למילה הבאה: זוגות מילים מוויקיפדיה, ו"פנקס" של הטקסט עצמו
   שלומד תוך כדי קריאה. מערבל שוקל אותם לפי כמה כל אחד צדק בטקסט הזה.
4. **מודל התבנית.** התווים שבין המילים עוברים מודל ערבוב-הקשרים קטן (הרעיון של PAQ בקטן).
5. **קידוד טווח.** ההסתברויות הופכות לביטים; המפענח מריץ אותם מודלים ומקבל בדיוק את אותו טקסט.

המצבים: **fast** - כל מילה בצעד אחד. **max** - גם איות אות-אחר-אות על עץ אלפביתי. **max_plus** - גם סוגי מילים,
וקטורי אמון לפי מצב וערוץ נושא. **חבילות שפה:** שפה היא שורות בהגדרות ועוד טבלאות; האנגלית משתמשת באותו קוד.

## מגבלות

- איטי לעומת zstd; באתר הוא רץ כפייתון טהור בתוך הדפדפן, ומקבל עד 16 KB.
- צריך את הטבלאות (25-191 MB) - זה הידע המוקדם שמאחורי התוצאות.
- היתרון העיקרי בטקסטים קצרים. נמדד על מחשב אחד, והקבוצות העבריות קטנות (28 טקסטים).
- טקסט מעורב עברית-אנגלית נדחס בחבילת השפה של הרוב; השאר נשמר בדיוק אבל נדחס פחות טוב.
