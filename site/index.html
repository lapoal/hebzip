hebzip

runs in your browser Source code and README

Lossless compression for short Hebrew and English texts. It works so well on short messages because it ships with prior knowledge: tables of words and word pairs built from Wikipedia (25.3 MB for Hebrew, 45.7 MB for English). It is also slow compared with gzip or zstd - here it runs as pure Python inside your browser.

Your text never leaves your browser. This page downloads only its own files (the engine and the tables, from this site) and sends nothing anywhere. No cookies, no analytics. Your browser keeps the downloaded files in its normal cache, so the next visit is fast.

The claim is narrow: short Hebrew (and English) messages, with the tables above
      shipped. paq8px, PPMd and the others start empty and learn only from the text itself - that is why short texts are hard for them.
      paq8px (GPL) is not shipped - build it and point the bench at it. The project texts were written by an AI
      model for the project. Reproduce everything with one command: python -m atar.bench run
      (in tools/compare_page; see the README).

  


  

    
How it works (short)

    

      
The text is split into words and the bytes between them. Each word is a number in a word list sorted by
        frequency. Several predictors guess the next word - word pairs counted on Wikipedia, and what this text
        has said so far (a notebook that learns while it reads) - and a trust mixer weighs them. The bytes
        between words go through a small context-mixing model. A range coder turns the probabilities into bits.
        The decoder runs the same models and gets exactly the same text back.

      
The website runs mode fast (Hebrew) and en_fast (English). The downloadable tool also
        has max and max_plus (letter-by-letter spelling, word classes, a topic channel; a few
        percent smaller, slower, bigger tables). Full method overview in the README.
